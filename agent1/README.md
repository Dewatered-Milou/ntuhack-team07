# CuriLoop — 雙向 AI 醫病溝通平台（Hackathon Demo 骨架）

Agent 1 病人端 demo：**照護問答**（個人病歷 grounding＋來源引用）與**每日症狀回報**（結構化＋紅旗規則分級）。醫師端摘要已獨立至同層的 `agent2/`。

前端已改為 React、TypeScript、Tailwind CSS 與 shadcn 相容結構。AI 回覆使用 `components/ui/ai-response-writer.tsx`，以固定高度卡片逐步顯示文字並自動捲到最新內容；來源、醫師確認狀態與安全處置卡仍保留。

輸入區使用 `components/ui/chatgpt-prompt-input.tsx`：支援多行自動增高、Enter 送出／Shift+Enter 換行，並把生活追蹤與營養諮詢模式整合進工具列。圖片目前只在瀏覽器本機預覽，不會送往 API；語音功能也清楚標示尚未開放。

啟動後會先顯示 Demo 登入頁。帳號為 `data/patients.json` 內的任一合成病患姓名，密碼只要非空即可；登入後會固定顯示該病患資料，直到按下登出。這只是前端展示流程，不是身分驗證或存取控制，正式環境不可沿用。

## 快速開始

```bash
cd agent1
npm install
npm start        # → http://localhost:3001
```

- **接上 GPT API**：在 Ver2 根目錄的 `.env` 填入 `OPENAI_API_KEY` 後重啟（預設 `gpt-5-mini`，可用 `AGENT1_OPENAI_MODEL` 更換）。跑 `node scripts/check-llm.js` 可驗證串接。
- **不設定金鑰也能跑**：自動進入「離線示範模式」，聊天與摘要用內建的個人化 mock 回答；**真 API 呼叫失敗也會自動降級 mock**，聊天不會死在台上——這就是 Demo Day 的斷網備案，請至少用它彩排一次。
- 也支援 Claude API 作為備選（填 `ANTHROPIC_API_KEY`；兩把都填時 OpenAI 優先，可用 `PROVIDER` 強制指定）。
- 回報資料存在記憶體，**重啟伺服器即重置回種子資料**，方便反覆彩排。

## Demo 劇本（對應 6 分鐘 pitch 的 2.5 分鐘實機操作）

1. **病人端**：選「王秀蘭」→ 點快速提問「我什麼時候可以恢復吃可化凝？」→ 展示回答引用她實際的用藥（Warfarin）、來源標籤、「需醫師確認・已加入回診問題清單」徽章。
   - **急症導流加碼（分兩步問，比一次到位更有說服力）**：切到「洪玉梅」（支架術後）先只打「我有點胸悶」→ AI 不會馬上叫 119，而是親切追問「還在嗎？會不會冒冷汗、喘、痛感傳到手臂？」——講點：資訊不足時系統會先確認，不是看到症狀詞就亂發警報。接著回「會喘，還一直冒冷汗」→ AI 立刻改判第 2 級「危急」、回答第一句叫她打 119，並跳出紅色處置卡（一鍵撥打 119／急診電話）。分級依據是官方檢傷表，不是 AI 自由發揮。
2. **每日回報**：填一筆「疼痛 6、體溫 37.8、傷口紅腫」→ 即時跳出黃色注意與原因；切到時間軸展示 8 天恢復軌跡。
3. **醫師端**（收尾畫面）：切到醫師端 → 30 秒摘要條列＋疼痛趨勢圖（黃/紅日期的資料點會變色）＋病人累積的待答問題清單——「醫師門診前 30 秒掌握 90 天」。
4. 加碼：切換到「陳柏睿」展示同一平台跨科（牙科 episode）。
5. 加碼（自費醫美市場）：切換到「陳怡安」（39 歲，Semaglutide 瘦瘦針第 9 週、剛升 1.0 mg）→ 問「打完針一直想吐正常嗎？」展示副作用衛教＋胰臟炎警訊；問「這週日晚上有事沒辦法打針怎麼辦？」展示漏打補打規則＋需醫師確認；輸入「上腹很痛還吐個不停」展示檢傷導流同樣適用於療程型個案。

**備援**：預錄一段以上流程的影片（牙醫系負責，17:30 前完成）。

## 醫師端資料包（/api/export）

把單一病人的**照護諮詢歷史（每筆含 ISO 8601 時間點）＋每日回報歷史**打包成結構化 JSON，供醫師端／醫院系統調閱分析：

```
GET /api/export/:patientId                       # 全部歷史
GET /api/export/:patientId?from=2026-08-11&to=2026-08-13   # 日期區間（含頭尾）
```

回傳格式（`resource_type: "careloop.patient_history_bundle"`，`version: "1.0"`）：

- `generated_at`：打包時間
- `patient`：病歷摘要（合成資料）
- `consultations`：`count`、`needs_doctor_confirmation_count`、`records[]`——每筆含 `timestamp`（時間點）、`question`、`answer`、`citations`、`needs_doctor_confirmation`、`triage_level`
- `daily_reports`：`count`、`stats`（與醫師端摘要同一套確定性統計）、`records[]`（含紅旗分級結果；當日新增的回報另含 `timestamp`）
- `pending_questions`：病人累積的待答問題（含時間點）

醫師端分頁也有「⬇ 下載資料包（JSON）」按鈕可直接下載，並新增「照護諮詢紀錄（含時間點）」卡片供回診前回顧。每一次 `/api/chat` 問答都會即時寫入諮詢歷史（demo 為 in-memory，重啟重置回種子資料）。

## 急症篩選設計（照護問答的安全層）

聊天回答除了衛教內容，還會依對照衛福部《檢傷分類民眾衛教版》判斷病人此刻描述的症狀屬於第幾級（1–4 級會跳出處置卡＋119／急診電話）。判斷分兩層：

1. **判級閘門（規則，`lib/llm.js` 的 `isAmbiguousSingleSymptom()`）**：實測發現 LLM 對「胸悶」「頭痛」這類單一症狀詞有很強的內建保守偏見——就算提示詞明確要求「單一症狀詞先追問、不要直接判危急」，模型還是常常直接叫病人打 119（這是安全調校模型的內建行為，很難用提示詞蓋過）。所以在呼叫 LLM **之前**，先用確定性規則判斷「這句話資訊夠不夠」：只提到症狀關鍵字、沒有其他修飾語（沒說多久、有沒有合併其他症狀、休息會不會好）→ 直接攔截，回一個追問，不呼叫 LLM。只要出現任何修飾語，或已構成官方表上的紅旗組合（如「胸悶＋冒冷汗」），一律放行給 LLM，不延誤。
2. **LLM 判級（線上模式）**：資訊足夠時才交給 GPT／Claude 對照完整檢傷表（含 TTAS 生命徵象量化基準）判斷 1–5 級，並結合病人病歷（如免疫低下、心臟術後）做個人化判斷。
3. **判為 1–3 級時，追問但不延誤**：answer 第一句話一定是「立刻打119／今天就醫」的行動指示，接著才追問意識、疼痛分數、放射痛、持續時間等不需工具就能回答的細節——「先行動、後追問」而非「問完才行動」。這些補充細節會存進醫師端的照護諮詢紀錄，回診時可完整回顧。

這個設計跟每日回報的紅旗規則（`lib/redflags.js`）同一套哲學：**安全判斷用可審核的規則守底線，LLM 負責需要脈絡理解的部分**——也是簡報上「AI 工具應用深度」可以講的細節。

## 合規紅線（簡報必講）

全部資料為**合成病歷**；產品定位為**醫師監督下的衛教輔助**（非診斷、非醫材）；紅旗判斷用**可審核的規則表**而非 LLM；正式版資料架構走**病人自主授權**（健康存摺 SDK／FHIR）。
